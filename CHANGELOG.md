### 0.24.1 — 2026-11-20

Исправления по ревью PR #2 (ichinya, коммит `adb57d8`).

- Windows: провайдер `aif-chat-worktree` принимает абсолютные пути Windows (`C:\…`, `C:/…`, `\\сервер\ресурс\…`), а не только пути с `/`. Хост перед вызовом git ещё раз проверяет путь правилами своей ОС. Ссылка `ref`, которая начинается с `-`, отклоняется.
- Windows: путь исполнителя в подпапке больше не заканчивается лишним `\`. Копия удаляется командой git из основного репозитория: git, запущенный изнутри копии, на Windows получал `Permission denied`.
- Возврат правок исполнителя: вместо `git apply --3way` и отката через `git checkout` — `git apply --check`, затем `git apply`. Без `--3way` патч применяется целиком или не применяется совсем и не трогает индекс: после отказа нет файлов `UU`, результаты прошлых задач целы. Patch-файл пишет сам git (`--output=`), без перенаправления оболочки, которое в PowerShell меняет кодировку. Тест выполняет команды прямо из текста инструкции.
- `Depends on 1-999999999` больше не перебирает весь диапазон: диапазон раскрывается только по номерам задач плана, а несуществующий конец диапазона по-прежнему даёт ошибку.
- `package.json`: версия и ссылки снова как у разработчика (`0.8.28`, `ichinya/bb-aif-helper`), порядок `files` как у разработчика, новые пункты в конце. Номер релиза задаёт ветка разработчика; версии форка ведутся в этом журнале.

### 0.19.0 — 2026-11-19

- Параллельное выполнение задач `/aif-implement`: у роли «Код» при «Другая модель» в «Исполнителях» появился переключатель **Параллельно** (Выкл · 2 · 3 · 4). Выбор хранится параметром `parallel` в `phases.implement.model` и попадает в «Модели по умолчанию» вместе с моделью.
- Группы задач считает плагин, а не агент: чистый модуль `parallel-plan.ts` разбирает `Depends on`, `Files:`, фазы и маркеры commit/deploy; пересекающиеся файлы, задачи без понятного списка файлов и одиночные commit/deploy не попадают в общую группу. Расчёт виден командой `bb plugin run aif-chat groups --target <план> [--max N] [--json]`.
- Каждая задача группы запускается отдельным тредом `AIF · <план> · <taskId>` в собственной git worktree-копии проекта от текущего коммита: координатор создаёт её сам (`git worktree add --detach <копия> refs/heads/<ветка>`) и запускает исполнителя на ней (`bb thread spawn --environment <копия>`), поэтому режим работает и в папке-проекте BB, где каждый плагин — отдельный репозиторий; исполнитель не коммитит, а координатор переносит правки патчами `git apply --3way` по одному с проверкой каждой задачи. Между группами — локальный коммит `chore(aif): …` без push. Чужие незакоммиченные изменения, конфликт патча или ошибка расчёта групп (ultra, OpenSpec, цикл) останавливают параллельный сценарий. В «В работе» у исполнителя в отдельной копии — метка «отдельная копия».
- При включённом режиме в `.ai-factory/skill-context/aif-plan/SKILL.md` появляется управляемый блок правила: у каждой задачи плана обязательны конкретные `Files:` и `Depends on`; при выключении блок удаляется.

- Результаты сохраняются по gate, чату и рабочей среде; следующий ответ и перезагрузка плагина не стирают предыдущий verify. Привязка требует явного canonical path в affected files или запросе запуска.
- UI показывает дату, номер сообщения, WARN/FAIL/PASS, blockers и причину рекомендации; файловый отчёт и неподтверждённая актуальность показаны отдельно. История читается ограниченными страницами по 100 событий, без запуска модели и записи evidence.

## 0.3.0 — 2026-11-02

- Обработка завершающего `aif-gate-result` из последнего ответа: отдельный блок статуса, blockers, affected files и рекомендации с причиной.
- Slash-рекомендации `suggested_next` становятся runtime-совместимыми кнопками; JSON-поля не сканируются как произвольные команды.
- Блокирующий gate останавливает commit/done/archive/implement, в том числе из workflow-карточки. Неблокирующий WARN сохраняет рекомендованный следующий шаг.
- Проверяется последний блок, схема и семантика; некорректный/незавершённый результат не заменяется старым PASS. Gate остаётся видимым после скрытия предложений.

## 0.2.0 — 2026-11-02

- Над полем ввода показываются команды `$aif…` из последнего ответа агента, отдельно от карточки workflow.
- У каждой команды есть крестик: скрытие сохраняется для этого текста ответа после перезагрузки, без отправки сообщений.
- Запуск сохраняет черновик, проверяет установленный skill и актуальность ответа; доставка использует общую защиту от busy/pending/queue, дублей и неопределённого результата.
- Разбор ограничен именами команд, без аргументов/окружающего текста; новые тесты покрывают два предложения, скрытие, переключение чатов, гонку обновления ответа и отправку.

## 0.1.3 — 2026-11-02

- Исправлено ложное «не установлен» для skills Codex в проектах с несколькими runtime: BB `codex-app` распознаёт общую `.agents/skills`, зарегистрированную как `codex` или `universal`.

- Добавлены регрессионные проверки discovery, `aif-analyze`, отсутствующих файлов и fingerprint; всего 55 тестов.
