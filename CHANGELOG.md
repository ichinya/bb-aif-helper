# История изменений

## 0.5.0 — 2026-11-02

- Общий кэш снимков в памяти и локальной SQLite-базе плагина. Вместо двухсекундного кэша на карточку — до минуты для обычного чтения; сохранённый снимок показывается сразу и обновляется в фоне. Кэш переживает reload, ограничен 100 снимками и 1 MiB на снимок; данные старше суток не используются для быстрого показа.
- Параллельные чтения одной рабочей среды/цели объединяются; этапы карточек и состояние чатов применяются отдельно. Чтение истории gate также объединено, сохранённые результаты показываются до фоновой сверки.
- Кнопка ↻, agent status/CLI и запуск действия явно обходят кэш. Фоновые ошибки сохраняют старую карточку с предупреждением и задержкой перед повтором; принудительное чтение возвращает ошибку, а не старые данные. Устаревший запрос не перезаписывает новый снимок после invalidation.
- Внизу карточки показаны источник, время снимка и фоновое обновление. Занятость и открытые вопросы читаются отдельно из актуального состояния BB.

## 0.4.0 — 2026-11-02

- Кнопки verify/rules/security/review, подготовки/прохождения QA, качества и CI перенесены в соответствующие строки секции проверок. Общий ряд кнопок снизу убран.
- На живом завершении валидного gate сохраняется отдельный отпечаток входов проекта. При неизменных входах повторный gate отключён с причиной «без изменений», в том числе через дублирующую workflow-кнопку и предложение команды. Сервер заново проверяет состояние перед отправкой.
- Отпечаток учитывает Git HEAD/index/diff/status, canonical target, установку, прочитанные metadata и содержимое неигнорируемых untracked files. Этап UI и время не сбрасывают блокировку. После изменения входов повторная проверка доступна.
- Старые отчёты не привязываются к сегодняшним файлам. Ошибки Git/чтения, превышение лимитов, submodules и неизвестная привязка оставляют повтор доступным. Это сравнение файлов с состоянием при фиксации результата, а не подтверждение PASS или готовности к done.

## 0.3.3 — 2026-11-02

- Кнопки предложений и workflow отправляют в видимый текст только выбранную команду. Служебные инструкции, привязка к плану/fingerprint и нормализованный JSON gate передаются отдельным SDK input с `visibility: agent-only`.
- Контекст и ограничения для агента сохраняются, а JSON больше не дублируется в новом пользовательском сообщении. Уже отправленные сообщения не редактируются.

## 0.3.2 — 2026-11-02

- JSON `aif-gate-result` в ленте по умолчанию свёрнут в строку «Данные gate» с типом и статусом. Раскрытие показывает исходный code block BB с копированием; сообщение и обработка gate не изменяются.
- Использован публичный `experimental_codeFenceRenderer` только для языка `aif-gate-result`. Другие JSON/code blocks не затронуты. Ошибки и прерванные gates видны вне свёрнутого блока; streaming не создаёт преждевременной ошибки JSON.

## 0.3.1 — 2026-11-02

- Исправлена секция проверок: завершённые verify/rules/security/review из `aif-gate-result` в истории чата теперь отмечаются для выбранного плана, даже когда файлового отчёта нет.
- Результаты сохраняются по gate, чату и рабочей среде; следующий ответ и перезагрузка плагина не стирают предыдущий verify. Привязка требует явного canonical path в affected files или запросе запуска.
- UI показывает дату, номер сообщения, WARN/FAIL/PASS, blockers и причину рекомендации; файловый отчёт и неподтверждённая актуальность показаны отдельно. История читается ограниченными страницами по 100 событий, без запуска модели и записи evidence.

## 0.3.0 — 2026-11-02

- Обработка завершающего `aif-gate-result` из последнего ответа: отдельный блок статуса, blockers, affected files и рекомендации с причиной.
- Slash-рекомендации `suggested_next` становятся runtime-совместимыми кнопками; JSON-поля не сканируются как произвольные команды.
- Блокирующий gate останавливает commit/done/archive/implement, в том числе из workflow-карточки. Неблокирующий WARN сохраняет рекомендованный следующий шаг.
- Проверяется последний блок, схема и семантика; некорректный/незавершённый результат не заменяется старым PASS. Gate остаётся видимым после скрытия предложений.

## 0.2.0 — 2026-11-02

- Над полем ввода показываются команды `$aif…` из последнего ответа агента, отдельно от карточки workflow.
- У каждой команды есть крестик: скрытие сохраняется для этого текста ответа после перезагрузки, без отправки сообщений.
- Запуск сохраняет черновик, проверяет установленный skill и актуальность ответа; доставка использует общую защиту от busy/pending/queue, дублей и неопределённого результата.
- Разбор ограничен именами команд, без аргументов/окружающего текста; новые тесты покрывают два предложения, скрытие, переключение чатов, гонку обновления ответа и отправку.

## 0.1.3 — 2026-11-02

- Исправлено ложное «не установлен» для skills Codex в проектах с несколькими runtime: BB `codex-app` распознаёт общую `.agents/skills`, зарегистрированную как `codex` или `universal`.
- Точное совпадение runtime остаётся приоритетным; каталоги других runtime не используются для совместимого поиска.
- Добавлены регрессионные проверки discovery, `aif-analyze`, отсутствующих файлов и fingerprint; всего 55 тестов.

## 0.1.2 — 2026-11-02

- Постоянная кнопка AI Factory в заголовке и отдельная вкладка справа.
- Панель читает статус своего чата без поиска карточки; открытие не отправляет workflow-команду.
- SDK harness проверяет открытие и thread scope; всего 51 тест.

## 0.1.1 — 2026-11-02

- Обновление AI Factory и запуск `aif`/`aif-analyze` независимо от плана.
- Обнаружение `aif-analyze` среди custom skills установленного `aifhub-extension`.
- Версии установки в fingerprint; updater-запрос сохраняет владельца установки и локальные изменения.

## 0.1.0 — 2026-11-02

- Карточки в чате и контекстной секции: версии, расширения, задачи и отчёты проверок.
- Маршруты upstream, AIFHub classic/OpenSpec и отдельный legacy ultra.
- CLI, agent tool и host RPC для read-only статуса.
- Защита от устаревших карточек, повторных кликов, неопределённой доставки и запуска во время работы.

Даты отражают подготовку локальных версий, а не публикацию в npm или создание GitHub Releases.
