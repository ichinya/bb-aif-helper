## Сценарий проверки `/aif-scout` — 0.8.36

Сценарий ручной проверки (выполняется после выкладки плагина):

1. В проекте с настроенными моделями «Разведчик 1–3» (или `self`) запустить `/aif-scout` по публичной теме (например, «на что жалуются пользователи менеджеров паролей») и подтвердить план ветвей поиска.
2. Если слоты заданы моделями BB — проверить в «В работе», что созданы дочерние треды с заголовками `AIF research · aif-scout · <angle>` на моделях выбранных слотов (без предупреждения `⚠ Ожидалась модель …`); при `self` разведчики идут собственными субагентами агента, дочерних тредов нет. В обоих случаях в `.ai-factory/scout/<slug>-<время>/` сохранены `plan.md`, ответы разведчиков `corpus/*.md` и `report.md` без создания или изменения `RESEARCH.md` и `INDEX.md`.
3. Проверить, что `report.md` показывает, сколько источников открыто полностью, фрагментами, только метаданными и недоступно, и заканчивается строками «Что установлено / Что пока неизвестно / Следующий шаг», а у разведчика, который не ответил или остановился раньше, в отчёте указано, что он успел найти.

## CLI-ограничение текущего BB на Windows

Короткий alias `bb aif-chat status ...` возвращает корректный JSON, затем процесс завершается с `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`. Контроллерский exit code — 1; это не записано как успешный CLI-run.

Устойчивые варианты, проверенные с exit code 0:

```text
bb plugin run aif-chat status --thread <id> --json
bb plugin rpc call aif-chat status --input-file <input.json> --json
```

Прямой HTTP RPC также возвращает `ok: true`. Native tool и кнопки используют SDK/RPC и не вызывают короткий alias. Его код BB в рамках этой работы не менялся; явный entrypoint указан в skill и подсказках агента.

В 0.23.0 (20 ноября 2026, Linux, слияние с 0.8.28): полный suite — **414 passed, 0 failed, 0 skipped**, TypeScript и сборка прошли. Тесты разработчика на его функции (одна карточка, скрытие при ожидании ответа, документ плана, исследование, завершённые планы, SessionBrief, 2.22, «Применить всё», причины недоступности) включены и проходят на нашей панели; обновление в них идёт через `experimental_invalidateRpc`, а не событие `changed`. На сервере нет `realtime.publish`, в UI — `setInterval` и `useRealtime`. Тесты на OVH запускаются под `systemd-run --user --scope -p MemoryMax=4G -p MemorySwapMax=0`.
