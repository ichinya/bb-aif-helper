# Настройки, CLI и устранение проблем

[README](../README.md) · [Workflow](workflow.md)

## Настройки

Откройте **Settings → Plugins → AI Factory Chat** или используйте:

```text
bb plugin config aif-chat
bb plugin config aif-chat set runtime codex-app
bb plugin config aif-chat unset runtime
```

Настройки относятся к установленному плагину. Рабочая папка определяется средой каждого чата; источник Git-версии и upstream задаются отдельно.

### `enabled`

По умолчанию `true`. Разрешает запросы статуса и добавление агенту tool/skill/instructions. При отключении запросы отклоняются; конфигурация агента меняется при следующем её разрешении BB. Зарегистрированные UI-поверхности сами по себе не удаляются.

### `sourceRepo`

По умолчанию пусто. Путь на хосте среды к checkout исходников пакета `ai-factory`, а не прикладному проекту. Не переключает рабочую среду чата.

Отдельно читаются версия `package.json` в HEAD, SHA, версия рабочего дерева и изменения отслеживаемых файлов. На удалённом хосте путь должен существовать именно там; общий путь может не подходить для всех хостов.

### `runtime`

По умолчанию `auto`. Значения: `auto`, `codex`, `codex-app`, `claude`, `cursor`, `opencode`, `gemini`.

В автоматическом режиме используется провайдер чата; для Codex выбирается `codex-app`. Если проект содержит несколько установок или выбор неоднозначен, задайте runtime явно. Настройка выбирает существующую установку, а не устанавливает новую.

Точное совпадение runtime имеет приоритет. Для `codex`/`codex-app` также поддерживается общая установка `.agents/skills`, зарегистрированная под другим Codex ID или `universal`, в том числе рядом с установкой Copilot. Это не разрешает брать skills из приватного `.codex/skills` для `codex-app` или из каталога другого runtime. Наличие каждого `SKILL.md` по-прежнему проверяется.

### `upstreamRepo`

По умолчанию `lee-to/ai-factory`; формат `owner/repository`. Проверяется только кнопкой **Проверить версию в GitHub** или командой `check-updates`.

Используются GitHub API и `raw.githubusercontent.com`, без токена. Аутентифицированная проверка закрытого upstream не поддерживается. В запросе передаётся настроенное имя репозитория/ref; содержимое локальных планов не отправляется.

### `upstreamRef`

По умолчанию пусто: последний стабильный GitHub release. Конкретный ref разрешается в commit SHA, затем версия читается из его `package.json` с проверкой имени пакета `ai-factory`.

```text
bb plugin config aif-chat set upstreamRef 2.x
bb plugin config aif-chat unset upstreamRef
```

Пример с `2.x` применим, если такой ref существует в выбранном upstream. Это источник проверки версии, а не команда checkout или обновления.

## Предложения из последнего ответа

Строка над полем ввода читает последний ответ агента через BB, а не всю историю, пользовательские сообщения или вывод shell. Найденные имена `$aif…` становятся отдельными кнопками: например, `$aif-architecture` и `$aif-roadmap`.

- Нажатие на имя отправляет только выбранную команду текущему агенту, сохраняя черновик.
- Крестик **×** скрывает одну команду без отправки сообщений. Он работает и при занятом агенте.
- Скрытие хранится в BB для данного чата, рабочей папки и текста ответа, переживает перезагрузку; при новом тексте ответа команды могут появиться снова.
- Повторы удаляются; распознаются имена, без аргументов и окружающего текста, не более 12 команд из первого 1 MiB ответа.
- Отсутствующий skill не запускается. Перед отправкой перепроверяются ответ, fingerprint, установка, занятость, очередь и открытые вопросы.
- Успешно отправленная команда убирается из этого списка; неопределённая отправка не повторяется автоматически и использует общую с workflow-карточками защиту доставки.

Строка привязана к обычному composer текущего чата; на экране нового чата и в редакторе очереди она не добавляется. Опрос раз в 15 секунд и события BB только обновляют предложения, без модельных вызовов. Если в ответе нет команд, дополнительное сканирование файлов проекта не требуется.

### Машинный результат gate

В 0.3.0 разбирается последний завершающий fenced-блок с языком `aif-gate-result`. Поддерживаются схема v1, gates `verify`, `review`, `security`, `rules` и статусы `pass`, `warn`, `fail`. Примеры внутри внешнего code fence и цитаты не считаются результатом. Незакрытый или повреждённый последний блок не заменяется более ранним успешным.

Над composer видны статус и `blocking`, список `blockers` с ID, severity, summary и file, раскрываемые `affected_files` и причина `suggested_next`. Этот блок остаётся видимым без предложений и после скрытия команды крестиком.

`suggested_next.command` проверяется по разрешённым командам gate и наличию skill. Имя адаптируется к runtime: `$aif-commit` для Codex, `/aif-commit` для slash runtime. Аргументы и произвольные shell-выражения не исполняются. При запуске владельцу skill передаются нормализованные данные gate как контекст, с требованием перепроверить их актуальность.

`WARN` должен быть неблокирующим с пустым `blockers`; `FAIL` — блокирующим с непустыми blockers. Для `PASS` требуется `suggested_next: null`, а дальнейшие команды могут быть указаны в тексте до gate. Противоречивый результат диагностируется; предложения из него не запускаются. При блокирующем gate команды commit/done/archive/implement блокируются, в том числе на сервере при запуске из workflow-карточки. Исправление и повторная проверка остаются отдельными действиями.

Поля JSON не сканируются как обычный текст с командами: имя `$aif…` в summary, reason или пути не создаёт дополнительную кнопку. Gate из ответа обозначается как **результат в ответе**, а не свежий PASS по файлам проекта.

## Команды

```text
bb plugin run aif-chat status --json
bb plugin run aif-chat show --phase plan --target .ai-factory/plans/my-feature.md
bb plugin run aif-chat check-updates --json
```

- `status` читает локальное состояние.
- `show` сохраняет выбранные цель/этап и возвращает директиву карточки.
- `check-updates` дополнительно читает GitHub upstream; ничего не устанавливает.
- `reset` очищает сохранённый выбор цели и этапа этого чата.
- `reset-dispatch` очищает историю доставки; применяйте только после проверки неопределённой отправки.

Общие аргументы:

- `--thread <id>` — по умолчанию текущий BB thread; вне его контекста задайте явно.
- `--target <path>` — относительный путь к обнаруженному плану/change; поддерживаются entrypoint и каталог с `index.md`/`tasks.md`.
- `--phase <phase>` — `unknown`, `explore`, `plan`, `improve`, `implement`, `verify`, `fix`, `done`.
- `--json` — структурированный вывод.

Пути вне проекта, переходы `..` и обращения к `.git` запрещены. При нескольких планах без однозначного соответствия ветке выберите цель; выбор по времени изменения не выполняется.

Просмотр CI — агентский сценарий bundled skill `aif-chat ci` и кнопка **Посмотреть CI**. Это не CLI-подкоманда `bb plugin run aif-chat ci`. Агент проверяет существующий run для нужного SHA через инструменты проекта; создание pipeline, push и перезапуск CI для просмотра не требуются.

## Частые проблемы

### «Нет установки»

Проверьте рабочую среду именно этого чата и наличие `.ai-factory.json`. Глобальный CLI не означает установку skills проекта. Соседний checkout расширения не считается установленным AIFHub. Плагин не выполняет `init` автоматически.

### Git-версия отсутствует

Настройте `sourceRepo` на исходники пакета AI Factory. При пустой настройке отсутствие Git-версии ожидаемо. Нестандартный layout глобальной установки тоже может остаться нераспознанным: версия определяется по metadata рядом с PATH shim, а не запуском CLI.

### Кнопка отключена

Проверьте подсказку и статус агента. Возможны отсутствующий skill, занятость, вопросы, очередь или противоречивые metadata. Дождитесь завершения текущей работы/ответьте на вопросы либо восстановите установку. Сервер повторно проверяет доступность перед отправкой.

### «Карточка устарела»

Нажмите **↻**, проверьте цель и выберите действие заново. Перед отправкой проверяется fingerprint исходников, установки и артефактов.

### Неопределённая доставка

При сообщении **Исход отправки не подтверждён** сначала проверьте ленту и очередь: команда могла быть доставлена. Плагин не повторяет её автоматически. Только после проверки и явного решения восстановить доставку выполните:

```text
bb plugin run aif-chat reset-dispatch
```

Это не отменяет уже запущенную работу и не доказывает, что предыдущая отправка не состоялась. Обычный сброс выбора — другая команда:

```text
bb plugin run aif-chat reset
```

Файлы проекта эти команды не меняют.

### Windows alias и GitHub

В проверенной Windows-сборке короткий `bb aif-chat ...` выдавал результат, затем завершался с libuv assertion. Используйте явный `bb plugin run aif-chat ...`. Кнопки и tool используют SDK/RPC.

При ошибке GitHub проверьте публичную доступность upstream и лимиты API. Непроверенная версия не заменяется предполагаемой.
